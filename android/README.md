# Market Deck for Android

A signed personal Android app with a dedicated graphite, lime and mint mobile interface. The bundled interface runs inside a restricted native WebView; native Java handles API requests, the server event stream and Android notifications. All market data, notes, watchlists, research, alerts and paper orders use the existing Market Deck backend. There are no separate mobile balances, sample prices or mobile trading engine.

## Install on Arpit's phone

Keep the existing **Termius port forward** running, and open **http://localhost:8790/android** in Chrome on that same phone. Download and install the APK. Android may require allowing installation from Chrome. Open Market Deck; its default server is `http://localhost:8790`. If Chrome uses a different forwarded port, enter that exact origin in the app's connection settings.

Tap **Enable notifications**, grant Android's notification permission, and keep the ongoing monitor notification active. Settings includes a phone notification test and a link to Android's notification settings. The test checks the phone, independently of server delivery.

## Notifications and practical limits

The server pushes events over `/api/mobile/stream` (SSE). Price **crossings**, completed/failed AI briefs and simulated fills become Android notifications. Creating an alert does not notify. Notification taps open the matching app screen. The existing event journal is the durable source: after disconnect, the app reconnects with its saved cursor and replays missed events. Notification IDs remain stable when an event is replayed. The first enable starts at the journal tip so historical activity does not flood the phone; recent history is available on the Alerts page.

This build uses a **private persistent connection**, not Firebase Cloud Messaging. It needs the Termius tunnel, the foreground monitor and notification permission. Android Doze, vendor battery restrictions, force-stop, a reboot or a lost tunnel can interrupt or delay delivery; it does not guarantee instant delivery with the phone asleep. Reopening the app restarts a previously enabled monitor after a reboot or force-stop. The ongoing Android notification has a Stop action. No boot receiver silently starts monitoring. For Google-managed cloud push without a persistent connection, a future version needs the user's Firebase project and server credentials; none have been invented or embedded.

The foreground monitor declares Android's `specialUse` type with its purpose in the manifest. This APK is for private installation. A future Play Store submission requires assessment of the service declaration and store policy; no store approval is claimed. Platform references: [notification permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission), [foreground service types](https://developer.android.com/develop/background-work/services/fgs/service-types).

## Screens and server calls

- Home: actual portfolio equity/cash/P&L, global index pulse, saved watchlist and latest research.
- Markets: symbol/name search, category filters, server watchlist, actual provider history, instrument notes, symbol tracking.
- Research: dated briefs, conditional ideas, provider provenance, failures and manual server generation.
- Portfolio: existing positions, modeled P&L/fees, paper orders. Orders require an explicit server preflight and confirmation; execution rechecks server risk limits and uses an idempotency key for retries.
- News: persisted headlines with search/source selection and original links opened outside the app.
- Alerts: server-backed price levels, triggered status and notification history.
- Settings: connection test, notification controls, feed health, server paper order pause/resume.

The app only accepts HTTP for localhost, `127.0.0.1` and the Android emulator's `10.0.2.2` bridge. Other configured origins must use HTTPS and already provide trusted private access. This work does not expose the server publicly, add a public proxy, or bypass Host/Origin checks. Port 8787 is untouched. For a phone with Termius forwarding, use the normal localhost address.

## Build and signing

Requires JDK 17, Android SDK platform 36/build-tools 36.0.0, and accepted Android SDK licenses. The Gradle wrapper pins Gradle 8.13 with its SHA-256; Android Gradle plugin is 8.13.0. The app targets API 36 and supports API 26+ with an updated Android System WebView. Java code has no third party runtime dependencies.

From the project root:

```bash
python3 android/build_apk.py
```

The helper uses `JAVA_HOME` and `ANDROID_HOME` when supplied, otherwise this host's tools in `~/.local/share/market-deck-build/jdk` and `~/.local/share/android-sdk`. First build creates a private signing keystore and password file under the ignored `data/` directory; later builds reuse them so updates install over this APK. Preserve these private files for future updates; never serve, commit or print them. The helper runs release assembly and lint, verifies the signature and atomically copies the APK to `android/dist/market-deck.apk`, with `SHA256SUMS` beside it. Package ID: `com.marketdeck.app`.

For Android Studio development, open this directory and use the debug build variant. To generate a release directly through Gradle, supply the private `MARKET_DECK_KEYSTORE` and `MARKET_DECK_SIGNING_PASSWORD` environment variables. Without them, a direct release assembly is unsigned. The helper is the standard signed release path.

## 1.5.1 — loss investigation and entry protection

User reported every closed trade losing and requested that negative points stop repeated bad trading. Audit found the fast exploration was too aggressive: it admitted eight correlated trials per bot before their outcomes arrived, then closed short-horizon episodes against a conservative modeled 0.80% fee on each side. The fee-only break-even price rise is `(1+0.008)/(1-0.008)-1 = 1.6129%`, before spread. Daily price change does not predict such a move over the holding horizon. Negative Q sizing and occasional exploration were insufficient protection.

Current live state: **entries_enabled=false; policy_enabled=false; enabled=true**. All new buys are blocked, including advisor buys; pending entry remainders are cancelled. Research/one-second worker and existing-position exit handling continue. Historical losses/fees/points and the original paper ledger are preserved. No claim of profitability or independent strategy validation is made.

Added: a three-consecutive-loss circuit breaker; refusal to repeat a context whose last completed episode lost; only one unresolved learning episode per bot/context; and a cost guard requiring sufficient real historical coverage and observed movement relative to the round-trip fee hurdle. Historical range is only a necessary cost filter, NOT proof of a predictive edge. Actual strategy reviews alone do not clear loss brakes; future entry resumption needs independent validation. Removed the old unconditional initial-trial fallback.

The app displays **NEW ENTRIES BLOCKED**, each bot's consecutive-loss brake and the 1.61% fee hurdle. Android 1.5.1/code 7 uses the existing key/package. 127 isolated checks pass (49 engine), populated web/mobile and live protection UI checks pass; release/lint/signature and live APK assets are verified. Reports: loss-guard-backend.json, loss-guard-live.json, loss-guard-ui.json and loss-guard-android.json.
