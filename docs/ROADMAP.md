# Five-phase roadmap

The roadmap is a specification and delivery record, not a promise of profitability or a claim every planned item is running.

| Phase | Purpose | Status |
| --- | --- | --- |
| 1 — Foundation | Preservation, scoped controls, private boundaries, readiness, source/receipt timestamps, model/CLI provenance, safe drafts and durable command identity | Foundation source and isolated verification delivered in the original workspace; public profile keeps AI off |
| 2 — Website | Cohesive black New Era interface, readable charts, search, source evidence, accessible/resilient interactions | Public observer delivered as a constrained feed-only experience; full terminal refinement remains broader work |
| 3 — Native Android | Native layouts, chart identity, per-origin repository, offline records, accessibility and upgrades | Native source exists; foundation resource health/latch work implemented; broader phase and handset release remain separate |
| 4 — Research and learning | Structured research, chronological experiments, uncertainty/abstention and owner-only evaluation | Existing deterministic descriptors are available; broader candidates/review desk are planned; no LLM weight training claim |
| 5 — Delivery | Exact artifact validation, preservation, signed compatible releases, performance, rollback and scoped activation | Incremental verification exists; production hosting/signed releases require separate gates |

The frozen base contains102 tasks. The working graph merges15 spatial tasks for117 total, validated as acyclic. The newest owner-selected black New Era/WebGL direction supersedes earlier mandatory Paper/Graphite or CSS-only mockup directions.

The public observer does not activate the full backend, paper simulation, optional CLI workflows or private deployment. Current US/NSE holiday verification, executable-book claims, model identity verification and profitability remain outside what the public page asserts.

See docs/roadmap/PLAN.md for the full specification and TASK_REGISTER_WORKING.csv for dependencies/acceptance details. Some historical references point to private artifacts intentionally not included in this public export; the public architecture and security documents define the supported distribution.
